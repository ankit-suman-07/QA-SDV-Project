## Comparable case

In two independent sessions, check out `e3b4a6af5421a3b9c88e2c16f51d78f929052990`.
Provide the same C2/C4/C5 requirements, session fixture and repository tools,
along with only the assigned skill text. Use the same model, permissions,
settings and time budget. Give each session this task:

> Assess whether a registered successor can resume recovery without letting a
> retired observation advance it. Run the existing offline check, point to
> the literal case results, and state what remains for live delivery acceptance.

Review each output against the same rubric: unregistered successor is rejected,
registered successor enters recovery with prior CRITICAL severity, retired
delivery is rejected, the exact command/revision/result is traceable, and
synthetic proof is distinguished from live binding and approval. Record model,
settings, tool calls, interventions, missed assertions, false claims,
corrections and reviewer. Compare coverage and effort and record ties or
drawbacks. Store both raw outputs and the review with Ankit's V2 evidence.
