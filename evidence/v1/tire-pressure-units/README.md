## Investigation and canonical boundary

Addresses [F02](../../../docs/findings/v1-implementation-verification.md), C4 and V1-05 baseline compatibility. VSS declares **uint16 kPa**. Generator state32/range30–34, historical legacy examples32psi, protobuf `tire_pressure_psi`, Ditto `tirePressurePsi`, and OpenSOVD28/24psi thresholds agree that synthetic numbers intend **psi**, not32kPa. See [historical contract](../../../docs/Version_1/04-vehicle-health-contracts.md), [investigation](investigation.json), generator history and current mapper. No authoritative requirement requires changing legacy field names or thresholds. This fixes inconsistent source/conversion boundaries rather than designing a new shared payload.

Canonical pipeline:

`generator internal psi → round(psi × 6.894757293168) → VSS uint16 kPa → kPa / 6.894757293168 → legacy protobuf/Thing/OpenSOVD psi`

The factor uses international pound-force/inch definitions. Convert **once at each boundary**. Generator state/random changes stay psi to retain physical behavior and fault progression. Publication never mutates state. The bridge converts kPa once before protobuf; mapper and existing psi fixtures never convert again. No pressure field is added to C3 LiDAR events or C4 LiDAR classification.

Whole-kPa quantization remains because VSS datatype is uint16: maximum roundtrip error0.5kPa≈0.07252psi.32psi→221kPa→≈32.05334psi;24psi→165kPa→≈23.93123psi;24.01psi→166kPa→≈24.07626psi;28psi→193kPa→≈27.99228psi. Threshold-near readings reflect quantization, not changed diagnostic thresholds. No exact sub-kPa precision or whole-psi rounding is introduced.
