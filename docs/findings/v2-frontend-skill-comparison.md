# V2 Fleet frontend skill comparison

This paired exploratory case study compares the same Fleet task starting at `700fc22a8f546b5159056242d95d85b6f0ba4388`. Run A used the original Anthropic skill. Run B used the SDV customization, which was informed by Run A's review findings. Run B read Run A's frozen checklist and reused its final browser harness before implementation. Run A's code, screenshots and review findings were opened after Run B froze its implementation and initial results. The runs were sequential, with one implementation per skill. These observations cannot isolate a causal skill effect.

## Skill changes and recommendation

The original skill calls for deliberate typography and composition, careful restraint and visual critique. The SDV derivative adds contract-to-UI mapping, sector-specific state semantics, shared muted tokens, component reuse and a narrow layout plan. It also requires selection-isolation checks, explicit synthetic boundaries and preserved initial evidence. These additions apply contract-first development and acceptance verification to a real operator view. Run B's mapping made the source clock and evaluation clock distinction explicit. Planning the narrow roster before coding removed the readability rework observed in A and led to a supplemental intermediate-width check. Both runs already omitted unsupported telemetry and separated execution from recovery, so those outcomes do not distinguish the skills.

Run B incurred additional planning and evidence work, and its initial V1 labelling failure shows that a stronger checklist does not guarantee compatibility. The reuse guidance did not yield a smaller stylesheet, and the muted palette alone did not produce a closer visual match. Driver setup and the matched reruns added verification work. Comparable token costs were unavailable. The derivative had the benefit of known Run A findings, and the final shared harness includes assertions added during Run A's review. The visual judgment is based on operator readability and the reference rather than a numerical image score.

Retain **Run A for the Fleet implementation**. Its corrected layout is closer to the reference, its narrow roster is more compact, and it labels stale metadata and legacy destinations more explicitly. Both final revisions passed the same synthetic harness. Retain the **customized skill for future dashboard work** for its contract mapping, preplanned narrow layout and reproducible evidence workflow. This recommendation concerns the frontend implementation and skill. Live acceptance and owner review remain separate.
